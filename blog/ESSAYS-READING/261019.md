# 读memory workflow相关调研报告

## 投机
### 是什么？
1. 投机的前身：`Speculative Execution`
CPU总是在等 -> 在if时猜一下分支吧
对了 -> 提交寄存器
错了 -> 刷新重算
低投入，成功了便高回报，是为“投机”。
2. 回到`投机`
原本：算完第n个token再算第n+1个 -> 慢
`优化`：预填未来K步，一次前向传播同时验证
如果出错 -> `止损`：在第一个出错token开始丢弃预测
### 怎么做？
投机的`猜法`：
1. N-Gram: Prompt Lookup Decoder, Trie树(如REST)
2. 小参数模型预跑
3. Medusa(多头并行) / EAGLE
4. Tree-based Drafting 树状多分支竞标

## LEANN
> 不保存所有Embedding，检索时按需重新计算 -> 用计算换存储空间

碎碎念：感觉应用场景很小，用AI的大家都急急的？
-> 不对，如果是大工程宁愿它慢点别出错

> 相关方法：
> 1. HNSW: 保存向量和邻接图，沿图寻找近邻 -> 索引占用较大
> 2. DiskANN: 利用 SSD 存储和访问图索引 -> 仍需保存向量或其压缩表示
> 3. IVF: 按聚类划分向量，先找相关簇 -> 可能需要扫描许多候选向量
> 4. PQ: 把高维向量压缩成短编码 -> 压缩过度会损害距离精度
> 5. LEANN: 保存压缩编码和稀疏图，必要时重算向量 -> 增加查询时的计算成本

## Medusa & EAGLE
1. Medusa
顾名思义，就是像美杜莎那样脑袋多多 -> 多头并行
这样看很云里雾里吗？是的，很云里雾里（）
所以问问AI就好理解多了：就是`投机`的时候`多几个预测头`。
> “这些 Head 先提出候选，随后主模型利用 Tree Attention 批量验证候选序列。”
2. EAGLE
> “Medusa 直接预测未来的 Token，而 EAGLE 先预测未来的隐藏特征（Feature），再根据这些特征预测 Token，从而让投机更准确。”
没错，就是`预测下一个 Feature，再预测 Token`。
