## 虚拟化
把硬件包装起来，使应用程序自以为拥有硬件
### 对CPU的虚拟化——进程
1. about
1个cpu，多个进程 -> 要切换
切换的过程：停止程序，运行另一个，称为`上下文切换`
选择进程 -> `调度`
2. concept
- 需要什么？
内存、cpu(寄存器，比如程序计数器PC、栈指针SP等)
- 好啦，现在虚拟化了cpu，还要向上给接口，给api，让应用程序管理硬件。
所以要可以创建销毁等待结束。
但是直接管硬件太累了，我们需要：
3. 系统调用
常见的调用：用户的这个函数跳转到那个函数
此处：`user -> kernel，用户态到内核态`
这种受控、进入内核、进入操作系统的机制，称为`trap(陷入)`
说回进程。我们要知道谁在跑谁在等，所以引出：
4. 进程的状态机
运行、就绪
e.g.
``` cpp
int x;
cin>>x;
```
要等到输入x了才能继续运行->感觉要讲单道了
->实则不然，要讲三态模型了
`就绪<->运行->阻塞->就绪`
因为要有始有终，所以加上边：`运行->终止，创建->就绪`

可是，谁来创建进程？-> 父子进程
进程都由进程创建，犹如鸡生蛋蛋生鸡无限循环
->第一个进程：和操作系统开机有关->`初始化进程`

5. 可是两个进程怎么在`运行、就绪之间转换`呢？
- 一开始：平进程的自愿
操作系统相信系统里的进程会自己合理运行
什么时候可以接管呢？
-> 进程自发进行系统调用的时候
显然，操作系统很被动，可以有坏进程无限循环
-> 设计强制事件，让cpu控制权回到操作系统手里
很符合直觉，是`时钟中断`
一开始：`协作式调度`；引入时钟中断：`抢占式调度`(目前基本都是)。

6. 未命名
找个东西存起来—>写个struct管管
->它就是PCB(process control block)

7. 回顾
此时已经把抽象过了一遍
`向下看`：os通过时钟中断、trap上下文切换，控制cpu在进程间来回切换 -> `cpu虚拟化`
`向上看`：os给了创建等待之类的接口，还维护了进程内部的数据结构PCB方便管理。
