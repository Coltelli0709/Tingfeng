# 第一章：计算机系统漫游

## 1.1 计算机的组成——一台机器长什么样

想象你面前有一台电脑。拆开机箱，你能看到什么？

一块**主板**，上面插着 CPU、内存条、硬盘，还有各种连线。这些连线统称**总线**。

```
┌─────────────────────────────────────────┐
│                    CPU                   │
│  ┌──────┐  ┌──────┐  ┌──────────────┐   │
│  │  PC  │  │ ALU  │  │ 寄存器文件   │   │
│  └──────┘  └──────┘  └──────────────┘   │
└──────────┬──────────────────────────────┘
           │  系统总线（地址+数据+控制）
    ┌──────┼──────┬──────────┐
    ▼      ▼      ▼          ▼
┌──────┐ ┌────┐ ┌────┐  ┌──────┐
│主存  │ │硬盘│ │键盘│  │显示器│
└──────┘ └────┘ └────┘  └──────┘
```

### 核心组件逐个解释

(1) **CPU（中央处理器）**——整台机器的"大脑"。它包含：
- **PC（程序计数器/指令计数器）**：记住一个核心知识点：`PC 存储的是"下一条将要执行的指令在主存中的地址"`。它像一个指针，告诉 CPU 下一步去哪取指令。★这是老师强调的书中配图知识点，必考。
- **ALU（算术逻辑单元）**：负责做加减乘除、与或非等运算。
- **寄存器文件**：CPU 内部的小型超高速存储，几十个寄存器，每个存一个字。

(2) **主存（Main Memory）**——也就是我们常说的"内存条"。CPU 能直接和主存对话，但**不能直接读硬盘上的数据**。硬盘数据必须先加载到主存中，CPU 才能用。

(3) **总线**——连接 CPU、主存、I/O 设备的数据通道。有三种：
- **数据总线**：传输实际数据
- **地址总线**：传输"数据在哪个位置"的地址信息
- **控制总线**：传输控制信号（读/写/中断等）

★老师特别提醒：第一章往年侧重计算而忽略文字概念，本次考试会涉及偏门配图和硬件名词，不可忽略。

### 真题速练

**题1-1** CPU 中有一个程序计数器（指令计数器），它用于存储（ ）。
A. 保存将要执行的下一条指令在主存中的地址
B. 保存当前 CPU 所要访问的内存单元地址
C. 暂时存放 ALU 运算结果的信息
D. 保存当前正在执行的一条指令

> **答案：A**。PC 存的是"下一条"指令地址，不是"当前正在执行"的那条。当前指令存在指令寄存器（IR）中，不是 PC。

**题1-2** CPU 能直接读取硬盘上的数据。这个说法对吗？

> **答案：错**。CPU 只能直接存取内存储器（主存）。硬盘数据必须先通过 I/O 总线加载到主存中。

**题1-3** 代码和数据被加载到（ ）后，处理器就开始执行 main 程序中的机器语言指令。
A. 主存  B. 寄存器  C. 程序计数器  D. 磁盘

> **答案：A**。程序必须先调入主存，CPU 才能逐条取指执行。

# 第二章：信息的表示和处理

这一章是整个课程的计算基础。核心问题：**数字在计算机里到底是怎么存的？**

## 2.0 前置知识：二进制与十六进制

计算机只认识 0 和 1。但写一长串 0 和 1 太痛苦了，于是我们用十六进制来"缩写"。

**十六进制的一位 = 4 个二进制位**：

| 二进制 | 十六进制 | 十进制 |
|--------|----------|--------|
| 0000   | 0        | 0      |
| 0001   | 1        | 1      |
| ...    | ...      | ...    |
| 1001   | 9        | 9      |
| 1010   | A        | 10     |
| 1011   | B        | 11     |
| 1100   | C        | 12     |
| 1101   | D        | 13     |
| 1110   | E        | 14     |
| 1111   | F        | 15     |

**转换口诀**：二进制 → 十六进制，从右往左每 4 位一组。十六进制 → 二进制，每位展开为 4 位。

例：`0x69` → `0110 1001`₂；`0xA5` → `1010 0101`₂。

题外：十进制 165 转十六进制：`165 ÷ 16 = 10 余 5` → `0xA5`。

## 2.1 「字节」到底是什么

- `●` 1 字节 = 8 个二进制位（bit）。
- 1 个字（word）在 32 位机器上是 4 字节，在 64 位机器上是 8 字节。

**题2-1** 通常所说的"字节"由（ ）个二进制位构成。 答案：B. 8

## 2.2 大小端——多字节数据怎么存放

一个 `int` 占 4 字节。比如 `0x01234567`（十六进制），它的 4 个字节从高位到低位是：`0x01`, `0x23`, `0x45`, `0x67`。

那么在内存中，这 4 个字节按什么顺序排列？有两种方案：

### 小端法（Little Endian）——x86/Linux 用的就是这种 ★

**规则：低位字节存在低地址，高位字节存在高地址**。

```
假设起始地址 = 0x1000

地址:  0x1000   0x1001   0x1002   0x1003
     ┌────────┬────────┬────────┬────────┐
     │ 0x67   │ 0x45   │ 0x23   │ 0x01   │
     └────────┴────────┴────────┴────────┘
       ↑ 低地址              ↑ 高地址
       存最低字节              存最高字节
```

记忆技巧：**小端 = "小"的在"低"地址**。最小的字节（0x67）放在最低的地址（0x1000）。

### 大端法（Big Endian）——网络传输常用

与小端相反：高位字节存在低地址。

```
地址:  0x1000   0x1001   0x1002   0x1003
     ┌────────┬────────┬────────┬────────┐
     │ 0x01   │ 0x23   │ 0x45   │ 0x67   │
     └────────┴────────┴────────┴────────┘
```

### 为什么考试常考？

考试最常见的题型是：给定一个 `int` 值和起始地址，在小端法下画出内存布局，或者给定内存布局反推值。做这类题的关键就是记住：**小端 = 低字节在低地址**。

**题2-2** `int x = 0x01234567;` 起始地址 `0x1000`，小端法下存储形式为：

> **答案**：`0x1000→0x67, 0x1001→0x45, 0x1002→0x23, 0x1003→0x01`

**题2-3** 小端法机器中，`int x = 0x123456;` 语句的高地址字节是（ ）。

> **答案：B. `0x00`**。int 是 4 字节，`0x123456` 只有 3 个有效字节，实际存储为 `0x00 0x12 0x34 0x56`。小端法下：`0x56, 0x34, 0x12, 0x00`，最高地址存的是 `0x00`。

## 2.3 位级运算——直接在二进制位上操作

C 语言提供了一组操作符，让你直接操作二进制位。这些运算在考试中大量出现。

### 六个核心运算符

| 运算符 | 名称 | 含义 | 例 |
|--------|------|------|-----|
| `&`    | 按位与 | 两位都是 1 才得 1 | `0110 & 0101 = 0100` |
| `\|`   | 按位或 | 至少一位是 1 就得 1 | `0110 \| 0101 = 0111` |
| `~`    | 按位取反 | 0 变 1, 1 变 0 | `~0110 = 1001` |
| `^`    | 按位异或 | 两位不同得 1 | `0110 ^ 0101 = 0011` |
| `<<`   | 左移 | 左移 n 位，右边补 0 | `0110 << 1 = 1100` |
| `>>`   | 右移 | 右移 n 位 | 见下文 |

### 算术右移 vs 逻辑右移 ★

这是考试的常规考点。

- **逻辑右移**：不管原来的符号，左边**一律补 0**。
- **算术右移**：左边补**符号位**（原来最高位是什么就补什么）。

```
例：8 位数 x = [10011101]₂（最高位 = 1，是负数）

逻辑右移 4 位：左边补 4 个 0 → [0000 1001]₂
算术右移 4 位：左边补 4 个 1（符号位）→ [1111 1001]₂
```

C 语言中，**无符号数用逻辑右移，有符号数用算术右移**（由编译器决定，但惯例如此）。考试题目会明确说是算术右移还是逻辑右移。

**题2-4** 对 `x = [10011101]₂`，x >> 4（算术右移）的结果是（ ）。
A. [11011001]₂  B. [00001001]₂  C. [11111001]₂  D. [10001001]₂

> **答案：C**。算术右移补符号位 1，左边添 4 个 1 得 `1111 1001`。

**题2-5** 对 `x = 0x85`，x >> 4（算术右移）的结果是（ ）。
A. 0x08  B. 0x50  C. 0xf8  D. 0x5f

> **答案：C**。`0x85 = 1000 0101`₂，最高位是 1。算术右移 4 位：左边补 4 个 1 → `1111 1000`₂ = `0xf8`。

### 逻辑运算：`!` `!!` `&&` `||`

这几个运算符的返回值**只能是 0 或 1**：

- `!x`：x 为 0 返回 1，x 非 0 返回 0。
- `!!x`：相当于"归范化"。非零值 → 1，0 → 0。非常实用！
- `a && b`：a 和 b 都非 0 才得 1。
- `a || b`：a 或 b 非 0 就得 1。

**题2-6** `!!0x21` 的结果用十六进制表示为（ ）。答案：**D. `0x01`**。

> 推导：`0x21 ≠ 0`，`!0x21 = 0`，`!!0x21 = !0 = 1 = 0x01`。

**题2-7** `!!0x77` 的结果用十六进制表示为（ ）。答案：**D. `0x01`**。同理。

**题2-8** `12 && 4` 的值是多少？答案：**1**。两个都非 0。

**题2-9** `(!0x15) > 16` 的值是多少？答案：**0**。`0x15` 非 0，`!0x15 = 0`，`0 > 16 = 0`。

**题2-10** 位级运算 `0x69 & 0x77` 的结果是（ ）。答案：**B. `0x61`**。

> 推导：`0x69 = 0110 1001`，`0x77 = 0111 0111`，按位与 → `0110 0001 = 0x61`。

注意区分"位级运算"和"逻辑运算"：
- `0x69 & 0x77 → 0x61`（逐位做与）
- `0x69 && 0x77 → 0x01`（逻辑与，结果只能是 0 或 1）

## 2.4 整数表示——补码是怎么来的

### 无符号整数

w 位无符号整数直接按二进制转十进制。范围：`0` 到 `2^w - 1`。

| 位数 w | Umax = 2^w - 1 |
|--------|----------------|
| 6      | 63             |
| 8      | 255            |
| 32     | 4294967295     |

### 补码（有符号整数）★

**核心思想**：最高位作为"符号位"，但不仅仅是符号——它还有**负权重**。

w 位补码数 `x = [x_{w-1} x_{w-2} ... x_1 x_0]` 的值为：

```
x = -x_{w-1} × 2^{w-1} + (其余位正常加权)
```

以 4 位为例：`[1011]₂ = -1×8 + 0×4 + 1×2 + 1×1 = -8 + 3 = -5`

关键常数（w 位）：

| 常数 | 公式 | 8 位 | 32 位 |
|------|------|------|-------|
| Tmax | `2^{w-1} - 1` | 127 | 2147483647 |
| Tmin | `-2^{w-1}` | -128 | -2147483648 |
| -1   | 全 1 | `1111 1111` | `0xFFFFFFFF` |
| 0    | 全 0 | `0000 0000` | `0x00000000` |

**特别注意**：Tmin 取负 = 自身（因为 `2^{w-1}` 超出 Tmax 范围，溢出）。

**题2-11** 32 位补码 integer 的最小值是（ ）。答案：**C. `-2^31`**。

**题2-12** 8 位补码的 Tmin 和 Tmax 分别是多少？答案：**Tmin = -128, Tmax = 127**。

**题2-13** 6 位字长补码的 Tmin 和 Umax 分别是多少？答案：**Tmin = -32, Umax = 63**。

### 有符号数与无符号数的转换 ★必考

转换时**位模式不变，只改变对位模式的解释方式**。这是老师说必考的概念。

```
例：short int x = -12345;  unsigned short int y = x;
问题：y 的值是多少？

解法：-12345 的 16 位补码位模式 = ？
12345 = 0x3039 = [0011 0000 0011 1001]₂
-12345 = 取反加一 = [1100 1111 1100 0111]₂ （16位）

当解释为无符号数时：按正数计算 = 53191
（不用死算，可用公式：unsigned = signed + 2^w = -12345 + 65536 = 53191）
```

**记忆公式**（w 位）：`有符号 → 无符号：if x<0, 则 ux = x + 2^w`

**题2-14** 8 位下 `(unsigned)((int)-7)` = ？答案：`-7 + 256 = 249`。

### C 语言中混合运算的类型转换规则

当一个有符号数和一个无符号数出现在同一个表达式中时，**有符号数被隐式转换为无符号数**。

**题2-15** 一个有符号数和一个无符号数执行运算后的结果是（ ）。
A. 有符号数  B. 无符号数  C. 非法运算  D. 不一定

> **答案：B**。C 语言会将有符号数隐式转为无符号。

**题2-16** 这是常考的坑题：

```c
unsigned int x = 0xDEADBEEF;
unsigned short y = 0xFFFF;
signed int z = -1;
if (x > (signed short)y) printf("Hello");  // (1)
if (x > z) printf("World");                // (2)
```

> **(1)** `(signed short)y`：`0xFFFF` 作为有符号 short = -1。`x > -1`？在有符号+无符号混合比较时，`-1` 转为 `unsigned = 0xFFFFFFFF`。`0xDEADBEEF > 0xFFFFFFFF`？不成立。Hello 不输出。
>
> **(2)** 同理，`z = -1` 转为 `0xFFFFFFFF`，`0xDEADBEEF > 0xFFFFFFFF`？不成立。World 不输出。
>
> 结果：**没有输出（A）**。

## 2.5 补码运算——计算机怎么做加减法

### 补码加法

规则很简单：**按二进制正常加，超出 w 位就截断**。

```
Tadd_w(u, v) = U2T_w[(u + v) mod 2^w]
```

四种情况（假设 u, v 都是 w 位有符号数）：

1. **正常**：`Tmin < u+v < Tmax`，结果正确
2. **正溢出**：`u+v ≥ Tmax`，结果 = u+v - 2^w（变成负数！）
3. **负溢出**：`u+v < Tmin`，结果 = u+v + 2^w（变成正数！）
4. **正常在范围内**

经典例子（4 位）：

```
Tmax(4) = 7, Tmin(4) = -8

0101 (5) + 0101 (5) = 1010 → 解释为补码 = -6（正溢出！5+5=10，10-16=-6）

1000 (-8) + 1111 (-1) = 1 0111 → 截断为 0111 = 7（负溢出！-9+16=7）
```

### 补码取负

几乎所有的数：`-x = ~x + 1`。

唯一的例外：**Tmin 取负等于自身**（因为 Tmin = -2^{w-1}，其正值 2^{w-1} 超出范围）。

### 一个重要的恒等式

`~x + ~y + 1 == ~(x+y)` —— 这个恒为真！

证明：`~x = -x - 1`（对于有符号数），所以 `~x + ~y + 1 = (-x-1) + (-y-1) + 1 = -(x+y) - 1 = ~(x+y)`。

**题2-17** 判断真假：`((x+y)<<4) + y-x == 17*y+15*x`。答案：**真**。（带入验证即可，对所有 x,y 成立）

## 2.6 浮点数——IEEE 754 标准 ★

### 为什么需要浮点数？

整数只能表示整数。要表示小数（如 3.14、科学计数法的 6.02×10²³），需要浮点数。

### IEEE 754 浮点数结构（必记）★

浮点数把 w 位分成三部分：**符号 | 阶码 | 尾数**

```
单精度 (float, 32位): [1位符号] [8位阶码] [23位尾数]
双精度 (double, 64位): [1位符号] [11位阶码] [52位尾数]
```

老师明确说：**浮点数存储格式（64位和32位结构）是必记内容，但不需要深挖复杂浮点运算**。

### 核心公式

```
V = (-1)^S × M × 2^E
```

- `S`：符号位。0 = 正，1 = 负。
- `M`：尾数（有效数字）。
- `E`：阶码（指数）。

### 偏置量（Bias）的概念 ★

阶码字段是无符号整数，但指数 E 需要表示正负。怎么实现？**减掉一个偏置量**。

```
Bias = 2^{k-1} - 1    （k = 阶码位数）

单精度：Bias = 2^{8-1} - 1 = 127
双精度：Bias = 2^{11-1} - 1 = 1023
```

### 三种情况（考试核心）★

**情况 1：规格化数（Normalized）——最常用**

条件：阶码不全 0 也不全 1。

```
E = exp - Bias
M = 1 + frac     ← 注意：隐含的"1."
V = (-1)^S × (1 + frac) × 2^{exp - Bias}
```

例（8位浮点：1符号+3阶码+4尾数，Bias=3）：
`0 100 0101`：
- S=0（正数）
- exp=4, `E = 4-3 = 1`
- frac=0101₂ = 5/16
- `M = 1 + 5/16 = 21/16`
- `V = 21/16 × 2^1 = 21/8 = 2.625`

**情况 2：非规格化数（Denormalized）——表示 0 和极小数**

条件：阶码全 0。

```
E = 1 - Bias        ← 注意：不是 0-Bias，而是 1-Bias
M = frac            ← 注意：没有隐含的 1
```

这样设计的好处：非规格化数能和规格化数平滑过渡（没有间隙）。

例：`0 000 0001`（8位）：E = 1-3 = -2，M = 1/16，V = 1/16 × 2^{-2} = 1/64。

**情况 3：特殊值**

| 条件 | 含义 |
|------|------|
| exp 全 0, frac 全 0 | ±0（根据 S 位） |
| exp 全 1, frac 全 0 | ±∞（根据 S 位） |
| exp 全 1, frac 非 0 | NaN（不是一个数） |

**题2-18** 8 位浮点数(1,3,4)中，哪个表示 NaN？
A. `1 000 1111`  B. `0 111 1111`  C. `0 100 0000`  D. `1 111 0000`

> **答案：B**。阶码全 1（111）且尾数非 0（1111）→ NaN。D 是负无穷大（exp 全 1，frac 全 0）。

**题2-19** 8 位浮点数(1,3,4)中，哪个表示 +∞？答案：**D. `1 111 0000` 是 -∞**。+∞ 是 `0 111 0000`。

**题2-20** 偏置量是多少（8 位，3 阶码）？答案：**Bias = 2^{3-1} - 1 = 3**。

### 浮点运算的特性

`●概念` `浮点加法满足交换律（a+b = b+a），但不满足结合律（(a+b)+c ≠ a+(b+c)）`。

为什么不满足结合律？因为**舍入误差**。

**题2-21** `(3.14 + 1e10) - 1e10` 的结果是（ ）。答案：**0.0**。

> 推导：`3.14 + 1e10` 时，3.14 需要**对阶**（对齐指数）。1e10 的指数远大于 3.14，3.14 被右移直到所有有效位消失 → 结果是 `1e10`。然后 `1e10 - 1e10 = 0.0`。这就是著名的「大数吃小数」现象。

### Round-to-Even（向偶数舍入）★

当数值无法精确表示为浮点数时，需要舍入。IEEE 754 默认使用**向偶数舍入**（Round-to-Even）：
- 如果超出部分 > 一半 → 向上舍入
- 如果超出部分 < 一半 → 向下舍入
- 如果超出部分**恰好等于一半** → 看最低有效位，它为 0 则舍（使结果为偶数），为 1 则入

这也是"银行家舍入"——避免统计上的累积偏差。

# 第三章：程序的机器级表示

这一章教你读懂**汇编语言**——C 代码编译后的"机器码"的可读版本。考试不要求你写汇编，但要求你能**从汇编反推 C 代码**。

## 3.1 x86-64 寄存器——CPU 内部的"变量"

CPU 内部有一组超高速的存储单元叫**寄存器**。x86-64 有 16 个 64 位通用寄存器：

| 64位名 | 32位名（低32位） | 16位名 | 8位名 | 用途约定 |
|--------|------------------|--------|-------|----------|
| `%rax` | `%eax`           | `%ax`  | `%al` | 返回值  |
| `%rbx` | `%ebx`           | `%bx`  | `%bl` | 被调用者保存 |
| `%rcx` | `%ecx`           | `%cx`  | `%cl` | 第4参数 |
| `%rdx` | `%edx`           | `%dx`  | `%dl` | 第3参数 |
| `%rsi` | `%esi`           | `%si`  | `%sil`| 第2参数 |
| `%rdi` | `%edi`           | `%di`  | `%dil`| 第1参数 |
| `%rsp` | `%esp`           | `%sp`  | `%spl`| 栈指针 |
| `%rbp` | `%ebp`           | `%bp`  | `%bpl`| 基址指针 |

**★重点记忆**：32 位寄存器前缀是 `E`（如 `%eax`），64 位前缀是 `R`（如 `%rax`）。操作 32 位寄存器时，高 32 位自动清零。`%ebx` 引用的是 `%rbx` 的低 32 位。

**题3-1** x86-64 中关于 `%rbx` 和 `%ebx` 的说法正确的是（ ）。答案：**B. `%ebx` 引用的是 `%rbx` 寄存器的低 32 位**。

## 3.2 操作数——指令操作的对象

汇编指令的操作数有三种形式：

| 类型 | 格式 | 例子 | 含义 |
|------|------|------|------|
| 立即数 | `$值` | `$0x204` | 就是值本身 |
| 寄存器 | `%r名` | `%eax` | 寄存器里的值 |
| 存储器引用 | `Imm(rb,ri,s)` | `(%eax)` | 内存地址里的值 |

### 存储器操作数 —— 寻址模式（必考）★

格式：`Imm(rb, ri, s)` = `M[Imm + R[rb] + R[ri] × s]`

- `Imm`：立即数偏移（可省略，默认为 0）
- `rb`：基址寄存器
- `ri`：变址寄存器（可省略）
- `s`：比例因子，只能是 1, 2, 4, 8（可省略，默认为 1）

常见缩写形式：
- `(%eax)` = `M[R[%eax]]` —— 寄存器间接寻址
- `0x204` = `M[0x204]` —— 绝对寻址
- `$0x204` —— 立即数
- `(%eax, %edx, 4)` = `M[R[%eax] + R[%edx] × 4]` —— 比例变址寻址
- `1(%eax, %edx)` = `M[1 + R[%eax] + R[%edx]]`

### 整道大题精讲（2015-2016 期中第三题）★

这是最经典的寻址计算大题，必须完全掌握。

**题3-2** 给定数据：

| 存储器地址 | 值 | 寄存器 | 值 |
|-----------|-----|--------|-----|
| 0x200 | 0xFF | %eax | 0x200 |
| 0x204 | 0xAB | %ecx | 0x1 |
| 0x208 | 0x13 | %edx | 0x3 |
| 0x20c | 0x11 | | |

求各操作数的值：

| 操作数 | 值 | 推导过程 |
|--------|-----|----------|
| `%eax` | `0x200` | 寄存器值 |
| `(%eax)` | `0xFF` | M[R[%eax]] = M[0x200] = 0xFF |
| `0x204` | `0xAB` | M[0x204] = 0xAB |
| `$0x204` | `0x204` | 立即数就是它本身 |
| `0x1fc(,%ecx,4)` | `0xFF` | M[0x1FC + 1×4] = M[0x200] = 0xFF |
| `(%eax,%edx,4)` | `0x11` | M[0x200 + 3×4] = M[0x20c] = 0x11 |
| `1(%eax,%edx)` | `0xAB` | M[1 + 0x200 + 3] = M[0x204] = 0xAB |
| `516(%ecx,%edx)` | `0x13` | M[516 + 1 + 3] = M[0x208] = 0x13 |

注：516 是十进制，516 + 1 + 3 = 520 = 0x208。

## 3.3 数据传送指令

### mov 系列

```asm
movq  S, D    # 64位传送
movl  S, D    # 32位传送（同时清零高32位）
movw  S, D    # 16位传送
movb  S, D    # 8位传送
```

规则：**源操作数和目的操作数不能同时是内存地址**。

**题3-3** 下面指令中错误的是（ ）。答案：**D. `movl 4(%rdx),(%rax)`**。

> mov 指令不能两个操作数都是内存引用。D 中源和目的都是内存地址，非法。

### mov 与 lea 的区别 ★

这是老师强调的重点概念，考试几乎必出。

- **mov**：从源地址**解引用**（即读取内存内容），然后传送到目的地。
- **lea**：只**计算**源地址（Effective Address），不访问内存，将计算结果存入目的地。

```asm
movq (%rax), %rbx    # 读取 M[R[%rax]]，存入 %rbx
leaq (%rax), %rbx    # 将 R[%rax] 的值复制到 %rbx（相当于 movq %rax, %rbx）

# lea 的真正威力在于利用寻址模式做算术：
leaq (%rax, %rcx, 2), %rdx    # %rdx = %rax + 2 × %rcx（不访问内存！）
```

**题3-4** `mov` 和 `lea` 的区别是（ ）。答案：**B. mov 需要解引用地址，lea 不需要**。

**题3-5** 与 C 代码 `eax = esi - 1` 对应的指令是（ ）。答案：**C. `lea 0xffffffff(%esi), %eax`**（`0xffffffff` = -1 的补码）。

**题3-6** `%eax = x, %ecx = y`，`leal (%eax,%ecx,2), %edx` → `%edx = ?` 答案：**C. x+2y**。

**题3-7** `leal 9(%eax,%ecx,2), %edx` → `%edx = ?` 答案：**D. 9+x+2y**。

### 栈操作

x86-64 的栈向**低地址方向**增长。

- **pushq S**：`%rsp = %rsp - 8`，然后 `(%rsp) = S`
- **popq D**：`D = (%rsp)`，然后 `%rsp = %rsp + 8`

记忆口诀：**push 先减后存，pop 先读后加**。

**题3-8** IA32 架构中，执行 `push %eax` 指令时，栈指针 `%esp`（加/减）4 后，再存储 `%eax` 的值。答案：**减**。

**题3-9** `%rsp = 0x108`，`popq %rax` 后 `%rsp = ?` 答案：**C. `0x110`**（+8）。

**题3-10** `%rsp = 0xdeadbeefdeadd0d0`，`pushq %rbx` 后 `%rsp = ?` 答案：**D. `0xdeadbeefdeadd0c8`**（-8）。

## 3.4 条件码与条件跳转

### 四个条件码寄存器

| 条件码 | 全称 | 含义 |
|--------|------|------|
| CF | Carry Flag | 进位标志（无符号运算的最高位进位） |
| ZF | Zero Flag | 零标志（结果为 0 则置 1） |
| SF | Sign Flag | 符号标志（最高位 = 1 则置 1） |
| OF | Overflow Flag | 溢出标志（有符号运算溢出） |

### cmp 和 test 指令

- **cmp S1, S2**：计算 `S2 - S1`，**只设置条件码，不存结果**。
- **test S1, S2**：计算 `S1 & S2`，**只设置条件码，不存结果**。

**题3-11** 零标志 ZF 表示什么？答案：**A. 零标志**。

### 条件跳转指令

| 指令 | 含义 | 跳转条件 |
|------|------|----------|
| je / jz | 相等/零 | ZF = 1 |
| jne / jnz | 不等/非零 | ZF = 0 |
| js | 负数 | SF = 1 |
| jns | 非负 | SF = 0 |
| jg | 有符号大于 | ~(SF^OF) & ~ZF |
| jge | 有符号大于等于 | ~(SF^OF) |
| jl | 有符号小于 | SF^OF |
| jle | 有符号小于等于 | (SF^OF) \| ZF |
| ja | 无符号大于 | ~CF & ~ZF |
| jb | 无符号小于 | CF |

**题3-12** 执行 `test %eax, %eax` 后 `jne 3d`。当 `%eax` 为（ ）时跳转？答案：**A. 1**。

> 推导：`test %eax, %eax` 做 `%eax & %eax`。当 `%eax = 0` 时，结果为 0，ZF=1，jne（ZF=0 跳转）不跳。当 `%eax ≠ 0`，ZF=0，jne 跳转。所以任何非零值（如 1）都会引起跳转。

## 3.6 循环的汇编实现

循环在汇编层面没有专门的"for"或"while"指令，而是用**条件跳转 + 跳回**实现。

典型的 for 循环汇编模式：
```asm
    movl $0, %eax        # i = 0
    jmp .L_test           # 跳到条件测试
.L_body：
    # 循环体
    incl %eax             # i++
.L_test:
    cmpl %edi, %eax       # 比较 i 和 n
    jl .L_body            # i < n 则继续循环
```

**题3-13**（2018-2019 期中第五题）根据汇编填 C 代码：

```asm
looper:
    xorl %eax, %eax       # %eax = 0 (x = 0)
    xorl %ecx, %ecx       # %ecx = 0 (i = 0)
    jmp .L25
.L27:
    movl (%rsi,%rcx,4),%edx   # edx = a[i]
    cmpl %eax, %edx            # 比较 a[i] 和 x
    jle .L28                   # a[i] <= x 则跳
    movl %edx, %eax            # x = a[i]
.L28:
    incl %eax                  # x++
    incl %ecx                  # i++
.L25:
    cmpl %edi, %ecx            # 比较 i 和 n
    jl .L27                    # i < n 继续
    ret
```

逐步分析：
1. 初始化 `x = 0, i = 0`
2. 循环：读取 `a[i]`，如果 `a[i] > x`，更新 `x = a[i]`
3. 无论是否更新，都执行 `x++`，然后 `i++`
4. 条件 `i < n`
5. 返回 `x`

所以 C 代码是：遍历数组找最大值，每步自增 1。

```c
int looper(int n, int *a) {
    int i, x = 0;
    for (i = 0; i < n; i++) {
        if (a[i] > x) x = a[i];
        x++;
    }
    return x;
}
```

## 3.7 switch 语句的跳转表 ★

switch 语句在编译时，如果 case 值比较密集，编译器会生成**跳转表**（Jump Table）而非一连串 if-else。

### 跳转表的工作原理

```
jmpq *Base(, %rax, 8)
```

这一条指令的意思是：`跳转到 M[Base + %rax × 8] 中存储的地址`。

Base 是跳转表首地址，表中每个条目 8 字节（一个地址）。`%rax` 是 case 索引（case 值减去最小值）。

### 完整实例解析（2017-2018 期中/期末均出现）

**题3-14** 给定跳转表（地址 → 跳转目标）和汇编代码，填写 C 代码：

跳转表索引 0~7：
```
[0]→0x4004d1  [1]→0x4004c8  [2]→0x4004c8  [3]→0x4004be
[4]→0x4004c1  [5]→0x4004d7  [6]→0x4004c8  [7]→0x4004be
```

汇编：
```asm
0x4004b0: cmp $0x7, %edx      # 比较 z 和 7
0x4004b3: ja  0x4004c8         # z > 7 (unsigned) → 跳到 default
0x4004b5: mov %edx, %eax      # %eax = z（索引）
0x4004b7: jmpq *0x400600(,%rax,8)  # 跳转表

# case 3/7 的代码：
0x4004be: mov %edi, %eax      # result = x
0x4004c0: retq

# case 4 的代码：
0x4004c1: mov $0x3, %eax      # result = 3
0x4004c6: jmp 0x4004da         # 继续（fall through）

# default / case 1/2/6:
0x4004c8: mov %esi, %eax      # result = y
0x4004d0: retq

# case 0 的代码：
0x4004d1: mov %edi, %eax      # result = x
0x4004d3: and $0x19, %eax     # result = x & 25 (0x19=25)
0x4004d6: retq

# case 5 的代码：
0x4004d7: lea (%rdi,%rdi,1),%eax   # result = 2*x
0x4004da: add %esi, %eax           # result = result + y
0x4004dc: retq
```

推导过程：
- z > 7 → default（result = y）→ 对应 case 的 default
- z = 3 或 z = 7 → `result = x; break;`
- z = 4 → `result = 3;` 然后 fall through 到 `result = result + y`
- z = 0 → `result = x & 25; break;`
- z = 5 → `result = 2*x + y; break;`
- z = 1, 2, 6 → default

答案：
```c
int test(int x, int y, int z) {
    int result = 3;
    switch (z) {
        case 0:  x = x & 25;        // 或 result = x & 25;
        case 3:
        case 7:  result = x; break;
        case 5:  result = 2 * x;
        case 4:  result = result + y; break;
        default: result = y;
    }
    return result;
}
```

**技巧**：做跳转表题目时——
1. 先找出 `ja` 或 `cmp` 的范围 → 确定 default 的目标地址
2. 标注每个跳转目标对应什么操作
3. 找出哪些 case 值对应相同的跳转目标（即 fall through 关系）
4. 注意 `break` 和 fall through 的区别

## 3.8 过程调用与栈帧

### 栈帧结构

每个函数调用都会在栈上分配一块空间，叫**栈帧**。栈帧包含：
- 返回地址（caller 中 call 指令的下一条地址）
- 保存的寄存器
- 局部变量
- 参数构造区

```
高地址
┌────────────┐
│  参数 n    │
│  参数 7+   │ (超过6个的参数通过栈传递)
├────────────┤
│  返回地址  │ (call 指令自动压入)
├────────────┤
│  旧 %rbp   │ (被调用者保存)
├────────────┤ ← %rbp（帧指针）
│  局部变量  │
│  保存的寄存器│
├────────────┤
│  参数构造区 │ (调用下一层函数时)
├────────────┤ ← %rsp（栈指针）
│     ↓      │
低地址
```

### 参数传递约定

x86-64 下，前 6 个整数/指针参数通过寄存器传递：
```
第1参数: %rdi    第2参数: %rsi    第3参数: %rdx
第4参数: %rcx    第5参数: %r8     第6参数: %r9
```

返回值放在 `%rax` 中。

**题3-15** x86-64 中 `%rsp` 和 `%rbp` 的用途是？答案：**C**。`%rsp` 是栈指针（指向栈顶），`%rbp` 是基址指针（指向当前栈帧底部，x86 时代常用，x86-64 下常省略）。

## 3.9 数组

`●概念` **嵌套数组采用行优先（Row-Major）顺序排列**。即一行的所有元素连续存储，然后下一行。

```
int A[2][3] = {{1,2,3}, {4,5,6}};

内存布局（行优先）：
地址:  A[0][0]  A[0][1]  A[0][2]  A[1][0]  A[1][1]  A[1][2]
     ┌────────┬────────┬────────┬────────┬────────┬────────┐
     │   1    │   2    │   3    │   4    │   5    │   6    │
     └────────┴────────┴────────┴────────┴────────┴────────┘
```

**多维数组寻址公式**：`&A[i][j] = xA + (i × N + j) × sizeof(T)`，其中 N 是列数。

### 经典真题（2017-2018 期中第九题）★

**题3-16** 从汇编指令反推数组维度 M 和 N：

```c
int array1[M][N];
int array2[N][M];
int copy(int i, int j) {
    array1[i][j] = array2[j][i];
}
```

汇编中出现的索引计算：
```
array2: 60*j + 4*i       → N个元素/行 × 4字节 × i偏移 + j偏移
array1: 36*i + 4*j       → 同上
```

推导：
- `array2[j][i]` 的地址 = `array2 + (j × M + i) × 4` = `array2 + 4M×j + 4×i`
- 汇编给出 `60×j + 4×i` → `4M = 60` → **M = 15**
- `array1[i][j]` 的地址 = `array1 + (i × N + j) × 4` = `array1 + 4N×i + 4×j`
- 汇编给出 `36×i + 4×j` → `4N = 36` → **N = 9**

**答案：M = 15, N = 9**。

## 3.10 结构体与数据对齐 ★

### 为什么需要数据对齐？

`●概念` 老师明确表示这是简答题考点：**对齐的目的是方便硬件按 4 字节批量存取数据，提升内存读写效率**。如果数据不对齐，CPU 可能需要两次访存才能读取一个跨越边界的数据。

### 对齐规则

x86-64 Linux 下，每种类型有对齐要求（等于其大小）：

| 类型 | 大小 | 对齐要求 |
|------|------|----------|
| char | 1    | 1        |
| short | 2   | 2        |
| int / float | 4 | 4     |
| long / double / 指针 | 8 | 8 |

规则：
1. **每个成员的偏移量必须能被其对齐要求整除**
2. **结构体总大小必须能被最大对齐要求整除**（末尾可能需要填充）

### 完整实例（2017-2018 期中第七题）★

**题3-17** x86-64 下结构体布局：

```c
struct my_struct {
    char a;             // 大小 1, 对齐 1
    long long b;        // 大小 8, 对齐 8
    short c;            // 大小 2, 对齐 2
    float *d[2];        // 大小 16(2×8), 对齐 8
    unsigned char e[3]; // 大小 3, 对齐 1
    float f;            // 大小 4, 对齐 4
};
```

逐步布局：

```
偏移 0:   a (1字节)
偏移 1-7: 填充 (7字节，使下一个偏移 = 8，满足 b 的对齐)
偏移 8-15: b (8字节)
偏移 16-17: c (2字节)
偏移 18-23: 填充 (6字节，使下一个偏移 = 24，满足 d 的对齐)
偏移 24-31: d[0] (8字节)
偏移 32-39: d[1] (8字节)
偏移 40-42: e[0..2] (3字节)
偏移 43: 填充 (1字节，使下一个偏移 = 44，满足 f 的对齐)
偏移 44-47: f (4字节)

总大小 = 48 字节（48 能被最大对齐 8 整除，不需额外填充）
```

表格式：

| 偏移 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|------|---|---|---|---|---|---|---|---|
| 0x00 | a | X | X | X | X | X | X | X |
| 0x08 | b | b | b | b | b | b | b | b |
| 0x10 | c | c | X | X | X | X | X | X |
| 0x18 | d[0] ... | ... | ... | ... | ... | ... | ... | d[0] |
| 0x20 | d[1] ... | ... | ... | ... | ... | ... | ... | d[1] |
| 0x28 | e[0] | e[1] | e[2] | X | f | f | f | f/end |

### 根据偏移量反推汇编操作数

在相同结构体下：

```c
void foo(struct my_struct *st) {
    st->a = 'e';           // a 在偏移 0 → movb $0x65, (%rdi)
    st->d[0] = NULL;       // d[0] 在偏移 0x18 → movq $0x0, 0x18(%rdi)
    st->c = 0x213;         // c 在偏移 0x10 → movw $0x213, 0x10(%rdi)
    printf(..., st->b,     // b 在偏移 0x8 → mov 0x8(%rdi), %rsi
              &st->f,      // f 在偏移 0x2c → lea 0x2c(%rdi), %rdx
              st->e[1]);   // e[1] 在偏移 0x29 → movzbl 0x29(%rdi), %ecx
}
```

### 优化：重排序减少填充

把对齐要求大的成员放前面，可以最大化空间利用率，减少填充字节。考试可能会问重排后最少多少字节。

**题3-18** 对上述结构体重排序，最少多少字节？

按对齐要求降序排列：b(8) → d(8) → f(4) → c(2) → a(1) → e(3)
总 ≥ 34，需对齐到 8 → 40 字节。答案：<del>48</del> **40 字节**。

但实际上原题选项是 A.48 B.36 C.40 D.以上都不是，选最大的无填充方案需要考虑 8 字节对齐——`long long` 和指针必须 8 字节对齐，排列后可能仍是 48。具体看考试的选项。

## 3.11 联合体 (Union)

**联合体的所有成员共享同一块内存空间**。大小 = 最大成员大小（对齐后）。

```c
union {
    char c;      // 1 字节
    int i;       // 4 字节
} u;
// sizeof(u) = 4
```

联合体在不同情境下解释相同的位模式，考试常考这种做法。

**题3-19**（2015-2016 期中第六题）IA32 小端法：

```c
union {
    unsigned char c[8];
    unsigned short s[4];
    unsigned int i[2];
    unsigned long k[1];
} dw;
for (j=0; j<8; j++) dw.c[j] = 0xc0 + j;
```

c[0..7] 的值：`[0xc0, 0xc1, 0xc2, 0xc3, 0xc4, 0xc5, 0xc6, 0xc7]`

- `dw.s[2]` = `0xc5c4`
- `dw.s[3]` = `0xc7c6`
- `dw.i[0]` = `0xc3c2c1c0`
- `dw.i[1]` = `0xc7c6c5c4`
- `dw.k[0]` = `0xc3c2c1c0`（IA32 下 long 为 4 字节）

ASCII: d=0x64 r=0x72 .=0x2e e=0x65 v=0x76 i=0x69 l=0x6c s=0x73

# 第六章：存储器层次结构

## 6.1 DRAM（动态随机存取存储器）★

这是老师明确标记为**高频简答**的考点。

### DRAM 原理

`●概念` DRAM 的每个比特存储在一个微小的**电容**中：
- 电容充电 ≈ 存 1
- 电容放电 ≈ 存 0

但电容会**持续漏电**！如果不加以维护，存储的信息会丢失。

`●概念` **刷新机制**：DRAM 控制器周期性（约每 64ms）读取并重写每个存储单元，补偿漏电损失。

`●概念` DRAM 是**易失性**存储：断电后数据丢失。需要持续供电 + 定期刷新。

### DRAM vs SRAM

| 特性 | SRAM | DRAM |
|------|------|------|
| 存储单元 | 6 个晶体管 | 1 个电容 + 1 个晶体管 |
| 速度 | 快 | 慢 |
| 成本 | 贵 | 便宜 |
| 用途 | Cache | 主存 |
| 是否需刷新 | 否 | 是 |
| 易失性 | 是 | 是 |

**题6-1** RAM 代表的是（ ）。答案：**C. 随机存储器（Random Access Memory）**。

## 6.2 传统旋转磁盘

### 磁盘容量计算

```
磁盘容量 = 盘片数 × 2面/片 × 磁道数/面 × 扇区数/磁道 × 字节数/扇区
```

**题6-2** 5 个盘片，每扇区 512 字节，每面 20000 磁道，每磁道 400 扇区：

容量 = `5 × 2 × 20000 × 400 × 512` = `40,960,000,000` 字节 ≈ `40.96 GB`。答案：**B. 40.96**。

**题6-3** 2 个盘片，每扇区 512 字节，20000 磁道，每磁道 400 扇区：

容量 = `2 × 2 × 20000 × 400 × 512` = `16,384,000,000` 字节 ≈ `16.4 GB`。答案：**C. 16.4**。

### 扇区访问时间

```
T_access = T_avg_seek + T_avg_rotation + T_avg_transfer
```

- 寻道时间：磁头移动到目标磁道的时间（机械运动，最慢）
- 旋转延迟：盘片旋转到目标扇区的时间（平均半圈）
- 传送时间：实际读写扇区数据的时间

**题6-4** 15000 RPM, T_avg_seek=8ms, 500扇区/磁道：

- 旋转延迟 = `60 / 15000 / 2 = 2ms`（半圈时间）
- 传送时间 = `60 / 15000 / 500 = 0.008ms`
- 总 = `8 + 2 + 0.008 ≈ 10ms`。答案：**C. 10**。

**题6-5** 扇区访问时间不包括（ ）。答案：**B. CPU 发起磁盘读时间**（这是发起访问之前的事，不属于磁盘自身访问时间）。

## 6.3 SSD 固态硬盘

`●概念` SSD 特点：更快速、低能耗、**写访问比读访问慢**、读写速度不相当。

**题6-6** 不是 SSD 特点的是（ ）。答案：**C. 读写速度相当**。（SSD 写比读慢很多）

## 6.4 局部性原理 ★

- **时间局部性**：刚刚访问过的数据很可能再次被访问。（例：循环中的变量 i）
- **空间局部性**：地址相邻的数据很可能被接连访问。（例：顺序遍历数组）
- **步长越大，空间局部性越差**。

**题6-7** 关于局部性，正确的是（ ）。答案：**A. 局部性包括时间局部性和空间局部性**。

# 第七章：链接

## 7.1 链接器做什么

将多个目标文件(.o)和静态库(.a)合并为一个可执行文件。两大任务：
1. **符号解析**：确定每个符号引用对应哪个定义
2. **重定位**：合并各模块的代码段和数据段，修改地址引用

## 7.2 静态库链接规则 ★

`●概念` 命令行的库文件按**从左到右**扫描。每个库 `.a` 只解析**在它之前**积累的未定义符号。

```
gcc p.o libA.a libB.a
```

扫描过程：
1. p.o → 记录其定义的符号，标记其引用的未解析符号
2. libA.a → 解析前面未解析的符号，但 libA 自己引用的符号记录下来
3. libB.a → 解析前面未解析的符号（含 libA 的引用）

**循环依赖问题**：如果 `libA.a` 引用 `libB.a` 的符号，且 `libB.a` 也引用 `libA.a` 的符号，就需要重复写出库名：

```
gcc p.o libA.a libB.a libA.a
```

**题7-1** `p.o → libx.a → liby.a` 且 `liby.a → libx.a`：

答案：**`gcc p.o libx.a liby.a libx.a`**。

**题7-2** `p.o → libx.a → liby.a → libz.a` 且 `liby.a → libx.a → libz.a`：

答案：**`gcc p.o libx.a liby.a libx.a libz.a`**。

# 第八章：异常控制流

## 8.1 进程与 fork ★

### 什么是进程？

进程是**正在运行的程序的一个实例**。每个进程有独立的虚拟地址空间（代码、数据、堆、栈），彼此隔离。

### fork() 函数

```c
pid_t fork(void);
```

`●概念` **fork 调用一次，返回两次**：
- 在**父进程**中：返回子进程的 PID（> 0）
- 在**子进程**中：返回 0
- 如果出错：返回 -1

子进程获得父进程的**独立副本**（写时复制优化）。父子进程拥有独立的地址空间，修改变量互不影响。

### 经典考题

**题8-1** 关于 `fork` 正确的是（ ）。答案：**A. 调用一次，返回两次**。

**题8-2**（2017-2018 期末第六题）

```c
int counter = 1;
int main() {
    if (fork() == 0) {        // 子进程执行
        counter--;            // 子进程的 counter: 1 → 0
        exit(0);
    } else {                  // 父进程执行
        wait(NULL);           // 等待子进程结束
        printf("counter = %d\n", ++counter);  // 父进程: 1 → 2
    }
}
```

输出：**`counter = 2`**。

> 关键理解：fork 后父子有独立地址空间。子进程修改自己的 counter 不影响父进程。

## 8.2 信号（Signals）★ 本次新增重点

信号是 Linux 中进程间通信的一种**异步通知机制**。老师明确说第八章是本次"重点补充章节"。

### 信号的基本流程

```
发送方（内核/其他进程）
    │
    ▼
  内核 ──转发──→ 目标进程
                 │
                 ├──→ 默认处理（如终止进程）
                 └──→ 自定义信号处理函数
```

### 未决信号（Pending Signal）★

`●必考` **未决信号**：信号已经由发送方发出、经由内核传递到目标进程、但目标进程**尚未接收和处理**的信号。

理解：就像有人给你打电话（发送信号），但你的手机设置了静音（进程在处理别的事情），电话在"未接来电列表"中等待你处理——这就是未决状态。

### 阻塞信号（Blocked Signal）★

`●必考` 进程可以通过函数设置**信号屏蔽**，被屏蔽的信号不会被接收处理，会保持未决状态。取消阻塞后，排队信号才会被处理。

`●必考` **同类信号排队**：进程正在处理某类信号时，同类新信号会排队等待，不会覆盖原有待处理信号。（但注意：Linux 中标准信号不排队——多次发送同一标准信号可能只被处理一次，这是考试简答需要区分的点）

### 进程的两位向量 ★必考

`●必考` 每个进程维护**两组比特位向量**，每一位对应一个信号编号（1~31）：

1. **未决向量（Pending Vector）**：位 = 1 表示该信号处于未决状态（已发送但未处理）
2. **阻塞向量（Blocked Vector）**：位 = 1 表示该信号被阻塞

```
例：未决向量 = [...0 1 0 1...]  表示信号 2 和信号 4 处于未决状态
    阻塞向量 = [...0 1 1 0...]  表示信号 2 和信号 3 被阻塞
```

只有当某信号的未决位=1 且阻塞位=0 时，内核才会将该信号递送给进程处理。

### 信号处理上下文切换 ★核心难点

`●必考` 这是老师强调的核心难点，涉及两种跳转方式的区别：

**(1) 普通跳转（如 setjmp/longjmp）**

- 保存内容：栈指针、参数、缓冲区数据
- **不保存**信号屏蔽状态
- 后果：如果在信号处理函数中阻塞了某信号，普通跳转返回后屏蔽状态不会恢复 → 该信号永远被阻塞 → 信号丢失

**(2) 信号专用跳转接口**

- 保存内容：除了栈和参数，**同时保存当前信号屏蔽向量**
- 恢复运行时，**还原屏蔽状态**
- 这是系统安全设计：确保信号处理程序返回后，屏蔽状态正确恢复，避免异常

**一句话总结**：普通跳转 ≈ 程序常规 goto；信号专用跳转 ≈ 程序 goto + 信号屏蔽状态的 snapshot/restore。在信号处理函数中只能用信号专用跳转。

**题8-3** 什么是未决信号？

> 答案：已由发送方发出、经内核传递到目标进程、但目标进程尚未接收和处理的信号。

**题8-4** 进程正在处理 SIGINT 时又来一个 SIGINT，会发生什么？

> 答案：新信号排队等待（标准信号可能丢弃重复；实时信号排队）。信号屏蔽机制确保当前处理不会被中断。

**题8-5** 为什么信号处理函数中要用信号专用跳转而不是普通 longjmp？

> 答案：普通跳转不保存和恢复信号屏蔽向量。信号处理程序中可能改变了屏蔽状态，用普通跳转返回会导致屏蔽状态无法恢复，造成后续信号接收异常和信号丢失。专用接口同步保存和恢复屏蔽向量。

# 第九章：虚拟内存

## 9.1 虚拟内存的基本概念

### 为什么需要虚拟内存？

1. **隔离**：每个进程有独立的虚拟地址空间，互不干扰
2. **方便**：程序可以使用连续的虚拟地址，不用管物理内存碎片
3. **安全**：一个进程不能直接访问另一个进程的内存

### 核心概念：地址翻译

CPU 发出**虚拟地址（VA）**→ MMU（内存管理单元）通过**页表**→ 转换为**物理地址（PA）**。

```
虚拟地址 VA ──→ [页表] ──→ 物理地址 PA
  VPN|VPO                    PPN|PPO
```

- **VPO（Virtual Page Offset）**：页内偏移 = 物理页内偏移（PPO），翻译中不变
- **VPN（Virtual Page Number）**：虚拟页号 → 查页表 → **PPN（Physical Page Number）**

## 9.2 TLB（快表）★

`●概念` TLB 是一个小型的硬件 Cache，缓存最近使用的页表条目，**加速虚→实地址变换**。

### TLB 结构（以 2 路组相联为例）

```
VPN 划分为：
├── TLBT（Tag）：高位，用于匹配
└── TLBI（Index）：低位，选择组

每个组有 E=2 个条目，每个条目 = {Valid, Tag, PPN}
```

### 完整大题精讲（2017-2018 期末第八题）★

这是 TLB 最经典的考题，必须逐行理解。

**题9-1** 虚地址 32 位，VPN 24 位，PPN 32 位，TLB 2路组相联 512 条目。

**(1) 各字段位范围**

- VPO（页内偏移）：页面大小 = 2^{32-24} = 256 B = `2^8` → VPO 占 **8 位**，即 **0-7** 位
- VPN：剩余的高位 → **8-31** 位
- PPO = VPO = **0-7** 位
- PPN：32 位 → **8-39** 位（物理地址 = PPN + PPO，总 40 位）

TLB 内部：
- 组数 = 512 条目 / 2 路 = 256 组 = `2^8` → TLBI 需要 8 位
- TLBI = VPN 的**低 8 位**（0-7 位，但取 VPN 视角）；
- TLBT = VPN 的高位（8-23 位，16 位）

整理成完整的位分配：
```
VA: [VPN: 24位 = 位31..8] [VPO: 8位 = 位7..0]
VPN: [TLBT: 16位 = 位23..8] [TLBI: 8位 = 位7..0]
PA: [PPN: 32位 = 位39..8] [PPO: 8位 = 位7..0]
```

**(2) 虚拟地址 `0x083F3E9A` 的翻译**

```
VA = 0x083F3E9A = [0000 1000 0011 1111 0011 1110 1001 1010]₂

VPO = 低 8 位 = 0x9A
VPN = 高 24 位 = 0x083F3E
TLBI = VPN 低 8 位 = 0x3E
TLBT = VPN 高 16 位 = 0x083F
```

查 TLB 表（题目提供）：

| Index | V | Tag | Entry(PPN) | V | Tag | Entry(PPN) |
|-------|---|-----|------------|---|-----|------------|
| 0x3D  | 1 | 0x083F | 0x0913ABDE | 1 | 0x083E | 0xAB18ED24 |
| 0x3E  | 0 | 0xF3E9 | 0x0913ABDE | 1 |**0x083F**|**0xAB18ED24**|
| 0x3F  | 1 | 0x409A | 0x0913ABDE | 1 | 0x083F | 0xAB18ED24 |
| 0x40  | 0 | 0x083E | 0x0913ABDE | 1 | 0x3E40 | 0xAB18ED24 |

TLBI = 0x3E → 查第 0x3E 组。该组第二路：Tag=0x083F（匹配！），Valid=1 → **命中**！

PPN = `0xAB18ED24`
PA = `{PPN, PPO}` = `{0xAB18ED24, 0x9A}` = `0xAB18ED249A`

**(3) 虚拟地址 `0x083E409B` 的翻译**

```
VPO = 0x9B
VPN = 0x083E40
TLBI = 0x40
TLBT = 0x083E
```

TLBI = 0x40 → 查第 0x40 组。第一路：Tag=0x083E 但 Valid=0；第二路：Tag=0x3E40 ≠ 0x083E → **不命中**！PPN 未知，PA 未知。

## 9.3 动态内存分配 ★ 分值占比高

### 堆（Heap）

- `●概念` 堆是虚拟地址空间中的一段区域，运行时通过 `malloc` 动态扩展，`free` 释放后收缩。
- 堆与栈的区别：栈由编译器自动管理（函数调用帧），堆由程序员手动管理。

### 内存分配器结构 ★需熟记

分配器在每块内存前后维护**元数据**（头部/脚部），通常包含：
- 块大小（含分配位）
- 是否已分配（1 bit，通常合并到大小最低位）

```
已分配块：
┌──────┬──────────────────────┬──────┐
│ 头部 │    有效载荷           │ 脚部 │
└──────┴──────────────────────┴──────┘

空闲块：
┌──────┬──────────┬──────────┬──────┐
│ 头部 │ 前驱指针 │ 后继指针 │ 脚部 │
└──────┴──────────┴──────────┴──────┘
```

### 空闲块合并 ★

`●概念` **合并规则**：当内存被释放时，分配器检查物理上**紧邻的前后块**是否空闲。如果空闲，则将它们合并为一个更大的空闲块，同时更新头部和脚部的大小信息。

为什么要合并？防止**碎片化**——大量小块空闲空间无法满足大请求。

### 空闲块检索方式

| 策略 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 首次适配 | 从头找第一个足够大的 | 简单快速 | 前部产生碎片 |
| 下次适配 | 从上次位置继续找 | 分布均匀 | 可能影响局部性 |
| 最佳适配 | 找最小的满足块 | 碎片最少 | 搜索开销大 |

**题9-2** 当调用 `malloc` 这样的 C 标准库函数时，（ ）可以运行时动态扩展和收缩。答案：**C. 堆**。

# 附：Cache（缓存）

## Cache 结构参数

- **S = 组数**，**E = 每组行数（相联度）**，**B = 块大小（字节）**
- 总容量 = S × E × B
- **直接映射**：E=1；**组相联**：1<E<全部；**全相联**：E=全部条目

## 地址划分

```
地址 = [CT: 标记位] [CI: 组索引] [CO: 块内偏移]
```

- CO = `log₂(B)` 位（块内字节的偏移）
- CI = `log₂(S)` 位（选择哪个组）
- CT = 剩余位（用于匹配）

## Cache 不命中率计算 ★

**题附-1**（2017-2018 期末第七题）

Cache：128 字节，2 路组相联，块大小 32 字节。`double A[32]`，代码：

```c
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        t += A[j*m + i];     // m*n = 32
```

**(1) 最多保存多少数组 A 元素？**
128 字节 / 8 字节(double) = **16** 个元素。

**(2) 有多少组？**
S = 128 / (2 × 32) = **2** 组。

**(3) m=1, n=32**（顺序访问 A[0], A[1], A[2], ...）
每 4 个元素一个冷不命中（块大小 32 字节 / 8 字节 = 4 个 double/块）。
不命中率 = 1/4。**有无时间局部性？无**（每个元素只访问一次）。

**(4) m=2, n=16**（访问 A[0], A[16], A[1], A[17], ...）
每次访问跳到 16 个位置之后。由于 Cache 只有 2 组，步长 16×8=128 字节，超过了 Cache 容量。
不命中率 = **1/2**。

**(5) m=16, n=2**（访问 A[0], A[1], A[2], ... 步长 2）
块内有 4 个元素，连续两个在块内 → 不命中率 = 1/4。**有无空间局部性？有**（相邻元素在 Cache 块内）。

# 附录：常见"坑"题汇总

## 坑1：有符号/无符号混合比较

```c
unsigned int x = 0xDEADBEEF;
signed int z = -1;
if (x > z) printf("World");  // 不输出！因为 z 被隐式转为 unsigned
```
z = -1 → 转 unsigned = `0xFFFFFFFF` → `0xDEADBEEF < 0xFFFFFFFF`。

## 坑2：浮点数大数吃小数

`(3.14 + 1e10) - 1e10 = 0.0`（不是 3.14）

## 坑3：sizeof 和数组

```c
int a[10];
sizeof(a) = 40   // 不是 4（指针大小）
```

但函数参数中的 `int a[]` 退化为指针，sizeof 返回 8（64位下）。

## 坑4：补码溢出

`TMax + 1 = TMin`（正溢出）
`TMin + TMin = 0`（负溢出截断）

## 坑5：小端读取

```c
int x = 0x01234567;
// 小端存储：67 45 23 01
// 按 short 读：s[0]=0x4567, s[1]=0x0123
// 按 byte 读：c[0]=0x67, c[1]=0x45, c[2]=0x23, c[3]=0x01
```

## 坑6：mov vs lea

```asm
movq (%rax), %rbx    # rbx = 内存[rax]    —— 读内存
leaq (%rax), %rbx    # rbx = rax           —— 不读内存，相当于复制
leaq (%rax,%rax,2), %rbx  # rbx = rax * 3 —— lea 的算术能力！
```
